MT7920 firmware
---------------
Source repository: official linux-firmware
Pinned commit: 87414f9ba8f875cb733281652474bccf93313e2f
Files:
- /lib/firmware/mediatek/WIFI_MT7961_patch_mcu_1a_2_hdr.bin
- /lib/firmware/mediatek/WIFI_RAM_CODE_MT7961_1a.bin

The Alpine firmware package did not contain the required MT7920 1a firmware pair;
the two files were added from the pinned upstream commit. The mt7921e module contains
the matching firmware request strings and a PCI alias for 14c3:7920.

Verification
------------
PASS:
- QEMU UEFI boot to Alpine login.
- GPT/ESP layout and EFI fallback loader.
- ext4 root mounted rw.
- Persistent marker survived guest reboot (marker subsequently removed from release image).
- apk packages persisted after reboot.
- dnsmasq DHCP lease issued to the FreeBSD test TAP client.
- DNS forwarding succeeded when a simulated WAN resolver was present.
- Isolated forwarding + conntrack + MASQUERADE test returned NAT_OK.
- iptables rules restored from persistent rules-save after reboot.
- sshd, dnsmasq, iptables and networking started after reboot.
- VMDK and QCOW2 qemu-img checks reported no errors.

LIMITATIONS:
- QEMU had no physical MT7920 device. wpa_supplicant was expectedly failed in the
  single-E1000 QEMU boot because wlan0 did not exist.
- Actual MT7920 PCI passthrough, firmware initialization, WPA association, WAN DHCP,
  and Internet access remain physical-hardware validation items.
- Wi-Fi SSID/passphrase were not supplied as confirmed values and are not embedded.
